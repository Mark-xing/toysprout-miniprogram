## 修复：表单输入框占位文字被垂直裁切（用户截图反馈）

用户截图 `Clipboard_Screenshot.png` 反馈登录页表单展示异常：手机号/验证码输入框占位文字被垂直裁切、文字贴在上边框，验证码按钮比输入框高。

### 根因（实测取证，非猜测）

小程序内置 `<input>` / `<textarea>` 自带 UA 样式：
- `height: 1.4rem`（约 22.4px）
- `line-height: 1.4rem`
- `overflow: hidden`

而 `miniprogram/app.wxss` 的 `.input, .textarea` 联合选择器设了 `box-sizing: border-box` 却**没有显式 `height`**。
于是垂直方向 `padding(20rpx×2 ≈ 20px) + border(1px×2)` 把内容区压到 **0.39px**，占位符与输入文字随即被裁掉。

实测数据（`mp.evaluate` + `wx.createSelectorQuery`，脚本 `/tmp/mp-measure-input.js`）：
```
.input computed: height=22.39px, lineHeight=22.4px, paddingTop/Bottom=10px, border=1px,
                boxSizing=border-box, overflow=hidden
内容区 = 22.39 − 20 − 2 = 0.39px
.btn--secondary height = 33px（与 22.4px 输入框不齐）
```

### 改动（3 文件）

| 文件 | 改动 |
|---|---|
| `miniprogram/app.wxss:181` | `.input` 显式 `height: 88rpx; line-height: 88rpx; padding: 0 24rpx` |
| `miniprogram/app.wxss:188` | `.textarea` 从 `.input, .textarea` 拆为独立规则，保留 `padding: 20rpx 24rpx` + `min-height: 160rpx` |
| `miniprogram/pages/login/login.wxml:33` | 验证码按钮去掉 `btn--sm` |
| `miniprogram/packageSwap/order-detail/order-detail.wxml:39` | 登记按钮去掉 `btn--sm` |

拆开选择器的必要性：否则 `.textarea` 会继承 `.input` 的 `height: 88rpx`，无法再用 padding 撑高度。

### 验证（`/tmp/mp-verify-form.js`）

```
.input  rect.height = 45px, lineHeight = 45px, paddingTop/Bottom = 0px
.btn--secondary rect.height = 45px
内容区高度 = 43.00px（修复前 0.39px）→ ✅ 足够容纳 14px 文字
输入框与按钮高度差 = 0.00px → ✅ 已对齐
```

### 经验沉淀（重要）

**小程序 WXSS 陷阱**：给 `<input>` / `<textarea>` 设 `box-sizing: border-box` 时，**必须同时给显式 `height`**。
否则 UA 内置的 `1.4rem` 高度会被自身 padding + border 吃掉，表现为「文字被裁、贴上边框」这类极具迷惑性的现象。

## P0 修复：点任意卡片都提示「玩具不存在」

**根因：组件自定义事件名撞了原生事件名 `tap`。**

组件是 `triggerEvent('tap', { id })`，页面写 `<toy-card bind:tap="onToyTap">`。
两侧名字对得上、各自看都没毛病，但 `tap` 是**原生事件名** —— 组件内部的原生 tap 会
**冒泡出组件边界**直接命中父级写在组件标签上的 `bind:tap`（这就是「点遮罩关弹窗」那个经典用法的原理）。
于是 `onToyTap(e)` 拿到的 `e.detail` 是原生事件的 `{ x, y }`（触点坐标）而不是 `{ id }`，
拼出 `?id=undefined` → 详情页查不到 → 报「玩具不存在」。

**实测取证**（劫持 `wx.navigateTo` 记录实际 url，对比两种事件形状）：

| 事件形状 | 实际跳转 | 结果 |
|---|---|---|
| 自定义 `{ id }` | `/packageToy/detail/detail?id=3f1b36026ac9db6d000419313e7e8b4d` | ✅ |
| 原生 `{ x, y }` | `/packageToy/detail/detail?id=undefined` | ❌ |

**修复**：`EVT_OPEN = 'open'` / `EVT_WANT = 'want'` 常量替换三处 `triggerEvent`；
`discover.wxml` 两处 `bind:tap` → `bind:open`；组件 JS/WXML 顶部补完整踩坑注释。

**为什么极易漏过**：① 两处代码名字一致；② 组件离线单测**全绿**（断言的正是组件自己发的事件名）。
只在真机用手点才现形。全项目扫过：`toy-card` 是唯一自定义组件，只有这一处。

**新增防线 `scripts/check-event-contract.js`（7 条，跨文件）**：
解析组件真正 `triggerEvent` 的名字 + 扫描所有 WXML 里该组件标签上的 `bind:`/`catch:` 名字，断言
① 组件事件名不得命中原生事件名黑名单；② 页面绑的名字必须真是组件会发的；③ 有文件在用该组件。
**反向对照已验证**：改回 `tap` 立刻 2 条 FAIL 并打印后果。

# 追加（第三轮）：详情页「点用积分兑换没反应」

## 根因（两层，第一层是正确行为，第二层才是 bug）

1. **服务端是对的**：那条玩具（`_id: 3f1b36026ac9db6d000419313e7e8b4d`「乐高」）的 `_openid` 就是当前用户
   真实 openid —— **它确实是自己发布的**。`points.previewShipping` 对它返回
   `400 不能兑换自己发布的玩具`（`cloudfunctions/points/index.js:47`）。
   逐件实测：**15 件里只有这 1 件失败，其余 14 件演示数据全部正常**。
2. **前端 bug**：`loadShippingPreview()` 拿到 `code !== 0` 后静默不 setData → `shippingPreview` 保持 `null`
   → `onRedeemTap` 在 `if (!sp) return;` 处**静默退出**，零反馈。任何预览拿不到的情况
   （接口报错/加载中/网络异常）都会让按钮变"死按钮"。

## 修复

| 位置 | 改动 |
|---|---|
| `cloudfunctions/toy/index.js` | `publicToy(t, ownerUser, viewerOpenid)` 新增下发 `isMine`（**放 `base` 内**，不放 `if (ownerUser)` 分支，保证拿不到作者文档时也能判断）；`enrichOwners` 一并加 `openid` 形参（工人发现的规格缺口：不加会 `ReferenceError` 被吞成 500） |

| `packageToy/detail/detail.wxml` | 自有玩具**不显示**两个按钮，换说明条 |

## ⚠️ 身份字段陷阱（本轮踩到，已加固）

- `users` 文档：`_id: aeb30c436ac9a62f0007d87741086bab`、`_openid: ohav85CnID4kBNChnkEgNKmEcgrA`
- `publicUser()` 下发的 **`id` 是 `_id`，不是 openid**；而全项目通用身份键是 **openid**
  （`toy.ownerId` / `swap.targetOpenid` / `wants._openid` 都是 openid）
- 两者都是长十六进制串、肉眼极易混淆。判断"是不是我的"**一律用服务端 `isMine`**，
  不要在前端拿 `userInfo.id` 比 `toy.ownerId`

## 新增防线 `scripts/check-detail-redeem.js`（35 条，离线）

Node 用 `require.cache` 注入 `utils/api` stub，直接加载 `detail.js` 真实方法体驱动，覆盖 12 组场景。
核心是**总闸门断言**：每个失败分支断言「`showToast` + `showModal` 次数之和 ≥ 1」= **点了必有反馈**。
原 bug 恰好会让它 FAIL。反向验证：`if (!sp) {…toast…; retry; return;}` 改回 `if (!sp) return;`
