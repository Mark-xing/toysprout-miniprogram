## 任务：部署上线（用户请求「把这小程序部署上线」）

### 重大发现：微信开发者工具 CLI 可用，但部署云函数有硬缺陷

CLI 路径 `/Applications/wechatwebdevtools.app/Contents/MacOS/cli`，本机已登录（`cli islogin` → `{"login":true}`）。

**可用**：
- `cli upload --project <path> -v 1.0.0 -d "<备注>"` → **真的能把小程序前端代码上传为开发版本**。
  实测成功，并回报真实包体积：main 97.7KB / packageToy 8.5KB / packageSwap 21.0KB /
  packageUser 33.0KB / TOTAL 160.3KB（限额 2MB / 20MB，占用极低）。
- `cli cloud functions deploy --env <envId> --names toy ...` → 对**不含量子目录**的函数可用
  （实测 `toy` 成功，9 files / 19.1KB）。

**不可用（重要）**：同一命令部署 `swap` / `auth`（它们的目录里有 `services/` 子目录）**必报**
```
{"code":"EISDIR","message":"Error: EISDIR: illegal operation on a directory, read"}
```
原因是 CLI 会把目录条目当文件读。`--paths` 换写法也一样失败；`toy`（无子目录）成功 →
**已隔离确认是"子目录"这个因素**，不是路径含中文、不是 config.json。
→ 结论：**含 `services/` 的函数（`auth` / `swap` / `membership` / `review`）只能用
CloudBase MCP 的 `manageFunctions(updateFunctionCode)` 部署，或由用户在 IDE GUI 里右键上传。**
反过来，MCP 通道**不读 `config.json`**（schema 里没有对应字段），所以 `config.json` 里声明的
openapi 权限只认 IDE GUI 上传那条路。

### 代码改动

1. **新建 `cloudfunctions/swap/config.json`** —— 声明 openapi 权限：
   ```json
   { "permissions": { "openapi": ["subscribeMessage.send"] } }
   ```
   依据：全仓唯一云调用点是 `cloudfunctions/_shared/notify.js:96` 的
   `cloud.openapi.subscribeMessage.send`；而**只有 `swap` 真正调用它**
   （只有 `swap/index.js:46` require 并调 `notifyAndPush`；`notify` 云函数只是复用
   `./notify` 里的 `COLLECTION` / `isCollectionMissingError` 常量，不发消息）。
   当前因模板 ID 为空而静默跳过，属于**潜伏缺陷**——一填上模板 ID 就会 100% 失败。
   ⚠️ 因为 MCP 不读 config.json，**这条权限要等用户在 IDE GUI 右键上传 swap 才真正生效**。

2. **修掉 `auth` 云函数把验证码回传给调用方**（原 `index.js:30`）：
   ```js
   // 改前
   return { code: result.code, devOnly: result.mock, expiresIn: result.expiresIn };
   // 改后（验证码只进服务端日志）
   console.log('[auth] sendCode 开发态验证码 phone=%s code=%s', phone, result.code);
   return { devOnly: result.mock, expiresIn: result.expiresIn };
   ```
   同时把 `index.js:52` 的用户可见文案 `'验证码错误，开发态验证码为 1234'` 改为 `'验证码错误'`。
   理由：固定码本身无害（无人可用它登录——账号键是 openid），但"接口把验证码告诉调用方"
   这个**形状**带上线后，等真接入短信网关会原地变成账号接管漏洞。
   已在线上实测：返回 `{"code":0,"data":{"devOnly":true,"expiresIn":300}}`，日志有码、响应无码。

3. **`scripts/run-integration-test.js`** 断言随之更新（184 → 186）。
   原来是 `check('sendCode 返回固定验证码', r.data.code === '1234')` ——
   这条断言把"泄漏"写成了期望值，方向是反的。改成三条：不回传明文 / 仍返回有效期与
   devOnly / 响应体整体不含 '1234'。
   **按纪律做了反向验证**：临时把 `code: result.code` 改回去 → 确认 2 条断言 FAIL
   （`PASS=184 FAIL=2`），再改回 → `PASS=186 FAIL=0`。
