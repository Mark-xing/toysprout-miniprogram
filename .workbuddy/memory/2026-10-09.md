**关键踩坑（勿重犯）**：
1. `wx-server-sdk` 的 `getTempFileURL` 的 `fileList` **只能传 fileID 字符串数组**，传 `{fileID, maxAge}` 对象会导致每项 `status != 0` 且**不抛异常**，表现为"静默不转换"——排查时极易误判为逻辑没生效。
2. 临时链接的 `t` 参数是**签名时刻而非过期时刻**（对比 maxAge=3600 与 86400 两次签发，`t` 都等于签发瞬间）。故有效期 = `t + maxAge`，无法从 URL 反推。wx-server-sdk 不支持指定 maxAge，实际时长未测得；因每次请求都重新签发，正常使用无影响。
3. `manageFunctions(updateFunctionCode)` 若函数正在 Updating 会返回 `FUNCTION_UPDATING`，须等 10s 再试，禁止连打。
4. 云端 curl 带 `sign=` 令牌的签名 URL 会触发敏感内容审批拦截，无法用 Bash 复测；改用 MCP 工具链取证。

## 登录方式决策：主体为个人主体 → 手机号快速验证不可用

用户确认 **个人主体** + 想全量改造。**冲突点**：`getPhoneNumber`（手机号快速验证组件）要求**非个人主体且已认证**，个人主体用不了。

能力对照结论：
- ✅ openid 静默登录：可用（**已在用**，`cloud.getWXContext().OPENID`）
- ✅ 头像昵称填写（`openType="chooseAvatar"` + `input type="nickname"`）：个人主体可用
- ❌ 手机号快速验证：个人主体**不可用**，需替代方案
- ❌ `wx.getUserInfo` / `wx.getUserProfile`：**已回收**（2021-04-13 / 2022-10-25），不再返回真实头像昵称，会误导用户，禁止使用

**建议方向**：把手机号从「登录前置条件」解耦为「收货地址里的收件联系方式」（地址管理已有该字段），登录只依赖 openid。这样个人主体也能做到「老用户 0 交互进入」。

**顺带发现的审核风险（待整改）**：
1. `utils/api.js` 收到 401 直接 `reLaunch` 到登录页 = **强制登录**，违反审核规范「基础功能不依赖登录」→ 建议改为发现页可匿名浏览
2. `app.js` 的 `checkPrivacyAndSession` **只打 console.log，从未真正发起隐私授权** → 接入任何个人信息收集前必须补 `wx.requirePrivacyAuthorize`
3. 二手交易类目对个人主体的开放情况需核实（可能阻塞正式上线）

## 经验：微信开发者工具自动化的 Page 级 API 不可用时应改用 mp.evaluate

IDE 2.01.2510290 + miniprogram-automator@0.12.1：`page.data()`/`page.$()`/`page.$$()`/`page.callMethod()` 全部挂死，但 `mp.evaluate()` 可用。**用 evaluate 在 app service 里跑 `getCurrentPages()` 取页面 data、调页面方法、调 `wx.cloud.callFunction`，是当前环境下唯一可行的真机验证路径。** 注意 evaluate 返回值序列化会丢嵌套数组，必须返回 JSON 字符串。
