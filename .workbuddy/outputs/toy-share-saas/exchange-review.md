## 一、5 维度评分与依据

### 维度 1：设计哲学 Philosophy —— 4/5

**依据（引用现象）**
- v2 信任主线忠实落地：人靠谱（信用分徽章四级「新芽/成长/信赖/优选」+ 实名/家长双认证 + 互评卡）、物如实（成色四级标签 + 实拍规范提示 + 适龄/小零件安全标签）、平台兜底（服务费保障条四变体 + 交换状态机 + 仲裁入口）**双端全站贯穿**，任何页面均出现 ≥2 类要素，非单页孤岛（满足令牌 §8.1）。
- 落地页（web/index.html）完整呈现「如何交换三步 + 信任三要素样例 + 会员对照 + 保障条」，营销→应用的承接清晰。
- C2C 双边气质成立：浏览端信用前置（玩具卡作者行带认证+信用徽章）、发布端实拍/成色约束、交换端一换一互邮说明、完成端互评信用反馈，闭环贯穿。
- **v1 语义彻底清除**：grep 双端产品页对「消毒/质检/批次/追溯/押金/租赁」0 命中；v2 安全提示仅表述玩具属性（适龄/小零件），无任何平台消毒承诺。
- 双端差异化成立：小程序=移动交互优先（拍照发布/聊天意向卡/会员免切换），Web=大屏决策管理（订单列表分组/免服务费计算器/会员对照表），页面非简单复制。

**扣分点**
- 收费透明的哲学承诺（"清晰如账本的规则透明"）被订单详情的「服务费双口径」削弱（见 P1-1）：同屏既显示「服务费已担保 ¥9.9」，又显示「会员免单 ¥0 · 立省 ¥9.9」，与"信任=清晰"的品牌哲学相悖。

**改进建议**
- 统一会员身份在订单生命周期内的费用呈现（详见 P1-1 修复方案），让「收费透明」在每一个页面都成立。

### 边界澄清：关于「月卡/年卡」术语
- 审查任务禁区内列出「月卡季卡年卡」为 v1 租赁语义，但需求 v2 §四与令牌 v2 §6.5.1 明文定义会员订阅为「月卡 ¥19.9 / 年卡 ¥168（推荐）」。经核对：**双端对「月卡/年卡」的使用均为 v2 会员订阅产品标签**，与 v1「平台自营租赁月/季/年卡+押金」语义无关；真正的 v1 语义（押金/消毒/质检/批次/追溯）产品页零命中。
- 建议（P2 文档级）：在主理人/需求侧对「会员订阅是否沿用『月卡/年卡』称谓」做一次口径确认，避免后续被误读为租赁语义；产品页无需改动。

## 三、问题清单

### P0（必须修复）

### P1（建议修复 · 阻断一致性上限 3 项已用满）

**P1-1 【最高优先】会员「服务费双口径」同屏矛盾（Web + 小程序订单详情）**
- 现象：web/order-detail.html 侧栏保障条显示「服务费已担保 ¥9.9 · 确认收货后放款」+「担保中」，同屏「服务费明细」又显示「服务费 ¥9.9（非会员）」「会员抵扣：会员免单 ¥0 · 立省 ¥9.9」；miniprogram/order-detail.html 保障条「服务费已担保 ¥9.9」与费用明细「本单合计 ¥9.9」并列。而当前用户 妈妈·小雨/小雨妈妈 全站已标为「会员年卡」（web/profile.html）、发起交换页会员态「¥0 立省」（web/swap.html、mini/swap.html 会员开关）。
- 判定：同一笔订单同时声称「¥9.9 担保中」与「会员免单 ¥0」，用户无法判断最终是否收费；直接伤害 v2「收费透明/平台兜底」信任承诺。
- 修复方案（任选其一，双端同步）：
  1. 订单详情按会员态呈现：「服务费已担保 ¥0 · 会员免单，本单立省 ¥9.9」（担保条改 `guarantee-bar--member` 变体），费用明细行改为「服务费：¥0（会员免）/ 合计：¥0」；
  2. 若该订单为「非会员视角」，则移除「会员免单 ¥0 · 立省 ¥9.9」行，并全局统一当前用户为非会员——**不可同屏并列两口径**。
  3. 小程序同理：swap 会员开关 → 订单详情的保障条与「本单合计」需联动为 ¥0（至少静态示例选择一致口径）。

**P1-2 Web 375px 状态机未按令牌转竖排（web/styles.css §28）**
- 现象：令牌 v2 §9.1 要求 <768px「状态机转竖排（与小程序一致）」，§6.4 移动 375px 明确竖排步骤条；当前 web 仅 `overflow-x:auto` + `.sm-node{min-width:72px}`，五节点约 430px 在 343px 内容区内横向滚动，未实现竖排。
- 修复方案：在 `@media (max-width:767px)` 增加竖排变体（复用 miniprogram 的 `.sm-row` 结构：状态一行 = 圆点+状态名+mono 时间戳，行高 48px；「双方邮寄中」内嵌双轨运单子卡），或将横排状态机替换为 mini 进度 + 当前状态徽章。

**P1-3 会员「信用分加成」双端口径冲突**
- 现象：web/membership.html 权益表「信用分加成」= 普通— / 月卡— / 年卡+5；miniprogram/membership.html 权益对照表 = 普通— / 月卡✓ / 年卡✓（且权益列表写「会员互评额外加权」，hero 也暗示所有会员）。
- 判定：同一产品双端给同一权益不同口径，家长对照双端会产生预期冲突。
- 修复方案：按需求假设收敛——建议以 Web 为准「仅年卡 +5」；若确为全体会员权益，则同步修改 Web 权益表与 index.html 定价卡（年卡行「信用分加成 +5」、月卡行「is-na 信用分加成」改为 ✓）。

### P2（可选优化）

1. 小程序会员中心默认选中「月卡」（plan-card--active）但 CTA 为「开通年卡 ¥168」，`pickPlan` 初始化未同步按钮文案 → `document.getElementById('open-btn').textContent = '开通月卡 ¥19.9'` 或默认选中年卡。
2. web/profile.html 菜单「收货地址与寄件信息」href 指向 orders.html（目标错误）→ 改为占位页/设置锚点。
