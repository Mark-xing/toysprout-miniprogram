## 一、业务分析（交换模型）

### 1.1 产品定位

【假设】产品为「**C2C 家长间玩具交换平台**」：每个家长可上传自家闲置玩具，浏览其他家长发布的玩具，选中后与玩具主人**聊天协商**，确认后**一换一互相邮寄**完成交换；平台在中间收取**介绍服务费**并提供信任机制与交易保障。双端结构：

- **小程序端（主阵地）**：移动场景高频入口 —— 拍照发布、浏览发现、消息聊天、交换履约
- **Web 端（管理与深度场景）**：落地营销、大屏浏览决策、订单管理、会员订阅、个人主页

**与 v1 的本质区别**：平台不持有任何玩具库存、不承担消毒质检（物品所有权始终在家长之间转移），平台的价值从「货的提供者」变为「**信任与撮合的组织者**」。

### 1.2 商业模式画布要点（交换模型）

| 模块 | 要点 |
|------|------|
| 价值主张 | 家长端：用自家闲置玩具**零现金成本**换回孩子想要的新玩具；解决「玩具堆积浪费」与「买新太贵」两大痛点；顺带环保互助、邻里社交。平台端：不持有库存，轻资产撮合双边市场 |
| 客户细分 | 核心：25–40 岁家长（0–10 岁孩子），C2C **双向角色**（既是发布者也是浏览者）；按孩子年龄段/城市/社区细分；种子用户来自母婴社群与幼儿园/社区口碑 |
| 收入来源 | **① 每单固定服务费 ¥1.9**（双方发起快递时收取，失败/取消不收）② **会员订阅 ¥10/月**（免每单服务费 + 优先曝光 + 专属客服 + 信用分加成）③ 二期：优先曝光竞价、品牌合作、数据服务 |
| 关键资源 | **用户池（双边供给与需求）**、**家长发布的玩具供给量**、**信用体系（信用分/互评）**、撮合匹配与聊天基础设施 |
| 关键活动 | **撮合匹配**（推荐/搜索/意向对接）、交易保障（服务费担保/纠纷仲裁）、社区运营（家长社群/口碑）、信用体系维护 |
| 关键合作 | **物流**（快递合作、寄件优惠/运费补贴）、支付渠道、实名认证服务、母婴社群/KOL、玩具品牌（未来闲置回收合作） |
| 渠道 | 小程序（主阵地）、Web、公众号/家长社群口碑 |
| 成本结构 | 平台研发运维、支付/物流合作成本、客服与纠纷仲裁人力、营销获客、信用风控 |

### 1.3 用户旅程与痛点（按交换四端）

> 与 v1 的「发现→决策→下单→使用→归还→留存」线性旅程不同，v2 是**发布/浏览双向并发 + 交换履约**的循环旅程。

| 阶段 | 用户行为 | 痛点 | 设计对策 |
|------|---------|------|---------|
| **发布端** | 拍照、填描述、定成色、发布玩具 | ① 拍照描述费劲（不知拍哪些角度、写什么）② 担心无人问津（曝光不足、石沉大海）③ 怕标错成色引发纠纷 | 拍照引导（多角度示例框/光线提示）、描述模板 + 成色标准自助指引、发布后曝光/浏览反馈即时可见 |
| **浏览端** | 浏览、搜索、筛选、查看详情 | ① **货不对板**（实物与图片/描述不符）② **不知对方是否靠谱**（信用不明、怕被放鸽子）③ 筛选不便（找不到适龄/想要的） | 成色标准徽章 + 实拍规范提示、主人信用分/认证标识前置展示、多维筛选（年龄段/品类/成色/同城优先） |
| **交换端** | 表达意向、聊天协商、确认交换、互寄 | ① 谈不拢（双方想换的玩具不匹配）② **谁先寄**（信任难题）③ 运费谁出、损坏责任谁担 | 标准化一换一流程、聊天内交换意向卡片 + 规则提示、邮寄状态双向追踪、服务费保障 + 平台仲裁入口 |
| **完成端** | 确认收货、互评、信用累积 | 评价动力不足（嫌麻烦、怕得罪人、不知评价意义） | 一键评价模板（星级+快捷文案）、信用分变化即时反馈、评价后解锁下一单/信用提升可视化 |

### 1.4 核心体验主线（重定义）：人靠谱 + 物如实 + 平台兜底

> v1 主线「平台消毒信任」**废弃**。v2 主线为 C2C 信任三要素 —— 这是贯穿双端全站的体验主轴：

| 要素 | 内涵 | 关键机制 | 设计承载（一等组件） |
|------|------|---------|---------------------|
| **人靠谱** | 对方是真实、可信、有交换记录的家长 | 信用分、实名认证、互评记录、交换历史 | 信用分徽章、认证标识、互评卡、交换达人标签 |
| **物如实** | 玩具状态与描述一致、不货不对板 | 成色标准、实物照片规范、描述模板 | 成色标签（全新/9成新/8成新/有使用痕迹）、实拍引导、成色对照说明 |
| **平台兜底** | 平台在中间为交易负责、出了问题有人管 | 服务费担保、纠纷仲裁、会员体系、物流合作 | 服务费保障说明、订单状态机、仲裁/客服入口、会员权益对比 |

> **设计结论**：三要素必须**全站贯穿**（列表卡、详情、订单、个人主页、聊天），而非仅存在于单页；信任语义从「绿=消毒安全」转为「绿=信用/如实」。

### 1.5 核心功能模块（首期）

1. **发布玩具**：多图上传 + 拍照引导、成色选择、描述模板、适龄/品类标签、交换偏好设置
2. **浏览发现**：推荐流/瀑布流、分类（品类/适龄）、同城优先、收藏心愿单
3. **搜索筛选**：关键词搜索 + 多维筛选（年龄段/品类/成色/同城/仅信用达标）
4. **交换意向与聊天**：发起交换（选我的玩具+留言）、双向确认、聊天协商（运费/邮寄细节）、意向卡片
5. **订单与邮寄状态**：一换一订单状态机（意向→确认→双方寄出→双方收货→完成）、物流单号追踪
6. **确认收货**：双向收货确认、异常/纠纷上报入口
7. **互评与信用**：5 星 + 文字互评、信用分动态、信用等级、评价后解锁
8. **会员订阅**：会员权益（免服务费/优先曝光/专属客服）、订阅与续费
9. **个人中心**：我的主页（信用分/我的玩具/我的交换/评价记录）、设置、地址与寄件信息

## 二、信息架构重设计（双端）

> 结构从 v1「仪表盘式管理视图」改为 **C2C 双边市场结构**：发现侧（浏览/交换）与关系侧（消息/信用/会员）并重。

### 2.1 Web 端页面清单（8 页）

```
① 落地页（营销层）                      品牌故事 / 如何交换三步 / 信任三要素 / 会员 / CTA
   └─ CTA → 注册/登录 → ②
② 平台首页·发现（应用层首屏）             推荐流 + 分类导航 + 搜索框 + 同城入口 + 顶部信用提示
   ├─ 玩具详情页                          图集 / 成色标签 / 适龄 / 主人信用卡 / 相似玩具 / 发起交换 CTA
   │    └─ 发起交换页                     选择「我的玩具」交换池 + 留言模板 + 服务费与规则确认 → 提交意向
   ├─ 我的主页                            信用分仪表 / 我的玩具（在换/可换） / 收到的评价 / 交换记录
   └─ 会员订阅页                          会员权益对比表 / 免服务费计算器 / 订阅按钮
③ 交换订单列表                           按状态分组（进行中/待收货/已完成/已取消）
   └─ 交换订单详情页                      双方玩具卡 / 邮寄状态双轨进度 / 确认收货 / 服务费说明 / 评价入口
```

### 2.2 小程序端页面清单（4 Tab + 子页）

```
Tab1 · 发现        发现首页（推荐/分类/搜索入口）→ 玩具详情 → 发起交换 → 等待确认
Tab2 · 消息        会话列表 → 聊天页（意向卡 + 协商 + 服务费/规则提示 + 订单入口）
Tab3 · 发布        发布表单（拍照引导 / 成色 / 描述 / 交换偏好）→ 发布成功（曝光提示）
Tab4 · 我的        个人中心（信用分 / 我的玩具 / 我的交换 / 评价 / 会员）→ 订单详情 → 评价页
                   └─ 子页：玩具详情 · 发起交换 · 订单详情 · 聊天 · 发布表单 · 评价 · 会员
```

**双端职责分工（Phase 3 原型遵循）**：
- 小程序 = **移动高频场景**：拍照发布、消息聊天、消息提醒、扫码/寄件提醒 —— 交互优先
- Web = **浏览决策与管理场景**：大屏详情、多玩具对比、订单管理、会员决策、个人主页 —— 信息密度优先

## 三、需求摘要（五要素框架）

| 维度 | 结论 |
|------|------|
| **场景 Surface** | **双端多页高保真原型**。Web 端 8 页（落地页、平台首页·发现、玩具详情、发起交换、交换订单列表、交换订单详情、我的主页、会员订阅页）；小程序端 4 Tab（发现/消息/发布/我的）+ 7 子页（玩具详情、发起交换、订单详情、聊天、发布表单、评价、会员）。需覆盖核心交互状态（交换状态机、聊天、信用分变化、会员订阅联动） |
| **受众 Audience** | 核心：25–40 岁家长（0–10 岁孩子），**C2C 双向角色**（既是发布者也是浏览者），非技术背景；关注「对方靠不靠谱、东西是不是如实、坏了/被骗了怎么办」；审美预期为「温暖亲子 + 邻里互助社区」，非儿童卡通 |
| **调性 Tone** | **延续 WarmTrust「温暖可信」基座**，叠加 **「邻里互助 · 环保分享」气质**。暖色系（奶油暖黄/暖米白）+ 鼠尾草绿（环保/信用语义）+ 珊瑚橙 CTA；圆角柔和、留白充足；从「消毒质检的工业化安全感」转向「**社区信任与个人信用感**」；克制专业，避免幼稚夸张 |
| **品牌上下文 Brand Context** | **童芽 ToySprout 延续**，品牌名与既有品牌资产沿用；设计系统 **WarmTrust 保留**，但信任组件语义**重构**（消毒/质检 → 信用/成色/互评，见 §1.4）；v1 的消毒报告卡、质检徽章、批次追溯条等组件**退役** |
| **规模 Scale** | 双端各 6–8 页，静态高保真为主 + 核心交互状态覆盖；Web 预留响应式结构，小程序按移动规范（底栏/手势/消息提醒）呈现；暂不做复杂动效与真实后端 |

### 推荐方向
- **建议设计系统类型**：WarmTrust v2（沿用并升级）—— 色彩/字体/圆角/间距令牌保留，**重构信任组件族**：新增「信用分徽章」「成色标签」「互评卡」「交换订单状态机」「服务费保障说明」，移除消毒/质检/批次类组件
- **建议原型模板**：C2C 双边市场模板（发现流 + 商品卡[带主人信用] + 聊天 + 订单状态机）+ 落地页模板（三步说明 + 信任区 + 会员区）
- **特别注意事项**：
  1. **信任三要素全站贯穿**：人=信用分徽章、物=成色标签、平台=服务费保障，必须出现在列表卡/详情/订单/个人主页，而非单页孤岛
  2. **一换一互邮状态机要清晰**：意向→确认→双方寄出→双方收货→互评，任一状态都要让双方「知道对方到哪一步了」
  3. **双端差异化落地**：小程序强调拍照发布/聊天/提醒（移动场景），Web 强调浏览决策/订单管理/会员（大屏场景），页面不可简单复制
  4. **定价与规则全部为【假设】值**，原型中以可配置文案呈现，并预留口径调整位

| **信用分** | ✅ **信用分以互评记录为准**，完成互评后动态更新；等级 500 新芽 / 600 成长 / 800 信赖 / 950 优选（1000 满）；仲裁败诉扣 20 分 |
| **互评** | ✅ 确认收货后 **7 天内**互评（**5 星 + 文字 + 快捷标签**），超时默认 5 星；差评可申诉（3 天复核）、恶意差评删除+警告；同用户 30 天内仅计 1 次；评价后信用分即时更新 |
| **实名认证** | ✅ **姓名 + 身份证号**；玩具安全：适龄+小零件发布必填，CCC（3C 目录内品类）提示选填上传，平台免责声明「家长自行确认安全性」 |
| **仲裁兜底** | ✅ 任一方申请 → **7 天举证期**（实拍照片+聊天记录+物流单号）→ **3 个工作日裁决**（退款/赔偿/继续履行）→ **败诉方扣 20 信用分**+记录仲裁历史；仲裁免费；丢件/损坏**谁寄出谁担责**，赔偿上限=双方估值（约 ¥100 内），贵重可保价 |

## 五、给 Phase 2 / Phase 3 的交接要点
