### 修复记录（2026-10-09）

**问题**：云函数侧 `db.collection().add()` **不会**自动注入 `_openid`（只有小程序端 SDK 才会），而读取侧全部用 `where({ _openid: openid })`，导致写入的数据永远查不到。

| 位置 | 改动 |
|---|---|
| `cloudfunctions/auth/index.js:43` | 建档 `data` 补 `_openid: openid` |
| `cloudfunctions/toy/index.js:166` | 改为 `data: { _openid: openid, ...input, ... }` |
| `cloudfunctions/user/index.js:106` | 改为 `data: { _openid: openid, ...input, ... }` |
| `scripts/mock-wx-server-sdk.js:124` | 移除 `add()` 里自动注入的 `_openid`（假绿根源） |

**真机验证结果（8/8 通过）**：首次登录返回的 user 已带 `_openid`；`user.getProfile` 由 401 转为正常返回；重复登录 userId 一致（不再重复建档）；`createAddress` → `listAddresses` 由 0 变 1；`updateAddress` 由恒 403 转为成功。
**反证实验**：临时注释掉 `auth` 的修复 → 本地测试立即出现 3 个 FAIL（`401 请先登录`）→ 证明测试已能守住该回归。
**数据清理**：测试残留（无 `_openid` 的 users ×3、孤儿 address、credit_logs ×3、points_accounts）已全部删除，9 个集合当前均为 0 条。

### 修复记录（2026-10-10）：表单输入框占位文字被垂直裁切

**现象**：登录页「手机号」「验证码」输入框的占位文字顶部被切、贴在上边框；同一行的验证码按钮比输入框高。

**根因**：小程序内置 `<input>` / `<textarea>` 自带 UA 样式 `height`、`line-height` 均为 `1.4rem`（约 22.4px）且 `overflow: hidden`。
原 `.input` 设了 `box-sizing: border-box` 却**没给显式 `height`**，于是垂直方向 `padding(20rpx×2) + border(1px×2)` 把内容区压到接近 0。

**实测取证**（`wx.createSelectorQuery` + `computedStyle`）：

| 项 | 修复前 | 修复后 |
|---|---|---|
| `.input` rect.height | 22.39px | **45px** |
| `.input` line-height | 22.4px | **45px** |
| 垂直 padding | 10px × 2 | **0px** |
| **内容区高度** | **0.39px** ❌ | **43.00px** ✅ |
| 与同行按钮高度差 | 10.6px | **0.00px** |

**改动**：

| 位置 | 改动 |
|---|---|
| `miniprogram/app.wxss:181` | `.input` 显式 `height: 88rpx; line-height: 88rpx; padding: 0 24rpx`（`88rpx` 与 `.btn` 默认高度一致） |
| `miniprogram/app.wxss:188` | `.textarea` 从 `.input, .textarea` 联合选择器**拆分**为独立规则，保留 `padding: 20rpx 24rpx` + `min-height: 160rpx` 撑高 |
| ~~`miniprogram/pages/login/login.wxml:33`~~ | 验证码按钮去掉 `btn--sm`。（该页已于同日按方案 A 改造为 `pages/profile`，此改动随之作废——资料页不再有验证码行） |
| `miniprogram/packageSwap/order-detail/order-detail.wxml:39` | 登记按钮去掉 `btn--sm`，同上 |

> ⚠️ **勿改回 padding 撑高度**：`.input` 必须显式给 `height` + `line-height`（两者相等即垂直居中），垂直方向不再用 padding。
> 该 `app.wxss` 规则被 6 个页面（profile / publish / verify / addresses / order-detail / swap）共 14 处 `.input` 复用，统一受益。

### 修复记录（2026-10-10）：头像选择器宽度被撑到 2 倍

**现象**：`pages/profile` 的头像选择按钮宽度异常，比预期正方形宽了近一倍。

**根因**：`<button>` 既是 flex 行（`.flex-row`）里的 flex item，自身又被设成 `display: flex`。
实测声明 `width: 176rpx`（390px 宽窗口下 = 91.52px），实际渲染成 **184px**，
而同一条规则里的 `height: 176rpx` 却是正确的 —— computedStyle 确认 `padding/margin/box-sizing/flex-shrink` 全部生效，唯独 `width` 落不下去。

**改动**：`miniprogram/app.wxss` 的 `.avatar-picker` 改为 `display: block` + `line-height` 居中（不依赖 flex），
并用 `min-width` / `max-width` / `min-height` / `max-height` + `flex: none` 把尺寸钉死；
`.avatar-picker__img` 改为 `width/height: 100%` 以适配 `border-box` 的内容区。

**实测对比**：

| 项 | 改前 | 改后 |
|---|---|---|
| `.avatar-picker` 尺寸 | 184 × 91 ❌ | **91 × 91** ✅（期望 91.52px） |
| `display` | flex | block |
| 是否达 44px 最小热区 | — | ✅ |

### 修复记录（2026-10-10）P0：点任意卡片都提示「玩具不存在」

**现象**：发现页改完之后，点击任意卡片都进不去详情页，提示「玩具不存在」。

**根因：组件自定义事件名撞了原生事件名 `tap`。**

组件原本是 `this.triggerEvent('tap', { id })`，页面写 `<toy-card bind:tap="onToyTap">`。
两侧名字对得上，**各自看都没毛病**，但这个写法是错的：

> `tap` 是**原生事件名**。组件内部的原生 tap 会**冒泡出组件边界**，直接命中父级写在组件标签上的
> `bind:tap`（这正是「点遮罩关弹窗」那个经典用法的原理）。于是 `onToyTap(e)` 拿到的
> `e.detail` 是原生事件的 `{ x, y }`（触点坐标），根本没有 `id`，拼出
> `url = '/packageToy/detail/detail?id=undefined'` → 详情页查不到 → 报「玩具不存在」。

**实测取证**（脚本劫持 `wx.navigateTo` 记录实际跳转 url，对比两种事件形状）：

| 喂给页面的事件 | 实际跳转 url | 结果 |
|---|---|---|
| 自定义事件形状 `{ id }` | `/packageToy/detail/detail?id=3f1b36026ac9db6d000419313e7e8b4d` | ✅ 正常 |
| 原生事件形状 `{ x, y }` | `/packageToy/detail/detail?id=undefined` | ❌ 「玩具不存在」 |

**修复**：

| 位置 | 改动 |
|---|---|
| `components/toy-card/toy-card.js` | 新增常量 `EVT_OPEN = 'open'` / `EVT_WANT = 'want'`，三处 `triggerEvent` 全部改用常量，并在文件顶部写下完整踩坑注释 |
| `components/toy-card/toy-card.wxml` | 头部注释补「对外事件名是 `open`（页面绑 `bind:open`），不能叫 `tap`」 |
| `pages/discover/discover.wxml` | 两处 `bind:tap="onToyTap"` → `bind:open="onToyTap"` |

**为什么这个 Bug 特别容易漏过**：① 两处代码名字一致；② 组件的离线单测**全绿**——因为断言的恰恰是组件自己发出的事件名。
它只在「真机上用手点」时才现形。全项目扫过一遍，`toy-card` 是唯一的自定义组件，所以只有这一处。

**新增防线 — `scripts/check-event-contract.js`（跨文件事件契约检查，7 条断言）**：
从组件 JS 解析出它真正 `triggerEvent` 的事件名集合，再扫描所有 WXML 里挂在该组件标签上的 `bind:` / `catch:` 名字，断言三件事：
① 组件对外事件名**不得命中小程序原生事件名黑名单**；② 页面绑的名字必须真的是组件会发的；③ 有文件在用该组件。
反向对照已验证：把事件名改回 `tap` 后该脚本立刻 2 条 FAIL，并直接打印出后果说明。
