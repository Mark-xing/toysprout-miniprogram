## 第四步补充：云存储跨用户可见性 ✅ 已用签名链接方案解决（无需升级套餐）

### 问题

环境云存储 ACL 被锁死在 **`PRIVATE`（仅创建者可读写）**。实测公开 CDN 地址匿名访问返回 **403**：

```
HTTP/2 403
server: TCB
```

后果：**用户 A 上传的玩具图片，用户 B 看不到**——发现页、玩具详情页、mine 列表全是破图。两个微信号互测时必现。

改 ACL 的尝试被平台拒绝（MCP `ModifyResourcePermission` 返回 Success 但 ACL 不变，换 `tcb storage rules update` 才拿到真实报错）：

```
OperationDenied.FreePackageDenied
[ModifyStorageSafeRule] 当前套餐无法执行此操作
解决方案：当前环境处于免费体验期，暂不支持开启该增值能力
```

即环境虽标记 `PackageId=baas_personal`，但 `EnvPaid=no` / `EnvActivated=no`，处于**免费体验期**，存储安全规则属增值能力。升级到付费个人版（**¥39.9/月**）可解锁，但测试阶段没必要花这个钱。

### 解法：云函数签发临时签名链接

原理：**云函数持管理员权限，用 `cloud.getTempFileURL()` 签发的链接不校验 ACL**，任何持有者都能匿名访问。因此在云函数下发数据前，把 `images` 里的 `cloud://` fileID 换成签名 https 链接即可。

新增共享模块 `cloudfunctions/_shared/storage.js`（由 `scripts/sync-shared.js` 分发到各函数目录），导出 `attachImageTempUrls(cloud, objects)`——就地替换传入对象数组的 `images`。

已接入的云函数（覆盖所有会返回玩具图片的接口）：

| 云函数 | 接入位置 | 覆盖的前端页面 |
|---|---|---|
| `toy` | `handleList` / `handleMine` / `handleDetail` / `handleCreate` / `handleUpdate` | 发现页、我的玩具、玩具详情、发布后回显 |
| `swap` | `handleDetail` 的 `myToy` / `targetToy` | 交换详情页的对方玩具图 |

### 实测证据（2026-10-09）

真实环境插入一条含三种图片取值的记录，调用 `toy.list` 返回：

```
[
  "https://636c-...tcb.qcloud.la/toys/_probe/acl-probe.png?sign=58d7...&t=1791539654",  ← cloud:// → 签名链接 ✅
  "https://example.com/keep.jpg",                                                      ← 非 cloud:// 原样保留 ✅
  "cloud://.../toys/_probe/missing.png"                                                ← 换取失败回退原值 ✅
]
```

1. **匿名拉取该签名链接：HTTP 200，下载内容 MD5 与源文件完全一致**（`17603f459a9cac4d8ac23104a1b062a9`）
2. **每次请求重新签发**：两次调用分别得到 `sign=edf617e2...&t=1791539491` 与 `sign=58d7deda...&t=1791539654`，签名为一次性快照
3. **单个文件失败不影响整条列表**——日志可见 `status:-503003, errMsg:"storage file not exists"` 被正确跳过
4. 本地集成测试新增 Section M 共 11 个用例覆盖上述分支，全量 **PASS=69 FAIL=0**

### 两个实现细节（踩过的坑）

- **`fileList` 必须传 fileID 字符串数组**，不能传 `{fileID, maxAge}` 对象形式——后者会让每项返回 `status != 0` 且不报错，表现为"静默不转换"。已实测，勿改回。
- **`t` 参数是签名时刻，不是过期时刻**。对比 `maxAge=3600` 与 `maxAge=86400` 两次签发：`t` 均等于签发瞬间，而 `expireTime` 分别报 3600/86400 秒。所以真实有效期是 `t + maxAge`，无法从 URL 反推。

### 已知边界

签名链接有效期由服务端默认策略决定（`wx-server-sdk` 无法指定 maxAge），具体时长未从接口读到。由于**每次拉列表/详情都会重新签发**，正常使用不受影响；仅当页面长时间驻留（跨过有效期）才可能出现图片失效，下拉刷新即可。若发现这个窗口太短影响体验，再考虑升级套餐改回公开读。

### 将来升级套餐后如何回退

把 ACL 改回「所有用户可读，仅创建者可读写」后，本兜底可以不删——`attachImageTempUrls` 只处理 `cloud://` 前缀，已是 http(s) 的值原样保留，多一次签名开销但功能无碍。若想彻底去掉，删除 `toy`/`swap` 中的 `withImageUrls` / `storage.attachImageTempUrls` 调用即可。

## 第六步：提交审核前的合规检查清单

> 微信审核对以下几项非常严格，任何一项不合规都会导致驳回，请逐条确认：

- [ ] **隐私协议**：小程序启动时必须有隐私协议授权弹窗（本项目已在 `app.js` 预留 `checkPrivacyAndSession`，需在【开发管理】→【服务内容声明】中完整填写"收集哪些用户信息、用途"）
- [ ] **用户协议**：建议在"我的"页面补充一个"用户协议/隐私政策"链接入口（本项目当前版本未包含独立协议页面，上线前需补充，可用云开发静态网页托管或直接嵌入文本页面）
- [ ] **类目选择**：提交审核时需选择合适的服务类目（如"社交-社区"或"电商-二手闲置"），不同类目审核严格度不同，二手交易类需谨慎选择，必要时补充资质
- [ ] **服务费/会员费提示**：任何收费环节必须清晰展示金额与用途（本项目已在服务费保障条/会员页明确展示 ¥1.9 / ¥10，符合要求）
- [ ] **禁止诱导分享/关注公众号弹窗**：本项目未包含此类逻辑，符合要求
- [ ] **包体积**：主包（`pages/` 4个页面）≤2MB，总包（含分包）≤20MB —— 部署前用微信开发者工具【详情】→【本地代码】查看实际大小
- [ ] **真实业务资质**（重要）：涉及"闲置物品交换+收费"的小程序，微信审核可能要求提供更多资质证明（如是否需要《网络交易经营者》相关备案），建议提交前咨询微信开放平台客服确认当前类目要求

## 后续真实资质接入指引

### 接入真实微信支付

1. 前提：小程序主体为**企业**，且已开通微信支付商户号（https://pay.weixin.qq.com）
2. 拿到商户号后，替换以下两个文件的内部实现（接口签名不变，调用方无需改动）：
   - `cloudfunctions/swap/services/payService.js`
   - `cloudfunctions/membership/services/payService.js`
3. 参考微信支付官方 Node.js SDK：https://github.com/wechatpay-apiv3/wechatpay-node-v3
4. 需新增一个云函数 `payCallback` 接收支付回调通知，验证签名后更新对应订单支付状态

### 接入真实短信验证码

1. 开通腾讯云短信服务（https://cloud.tencent.com/product/sms）或阿里云短信服务，获取 SecretId/SecretKey
2. 替换 `cloudfunctions/auth/services/smsService.js` 内部实现
3. 建议同时创建 `sms_codes` 云数据库集合存储验证码（含过期时间字段），避免验证码硬编码

### 申请手机号快速验证能力（可选，提升登录体验）

1. 在小程序管理后台【开发】→【接口设置】搜索"手机号快速验证"，查看当前账号是否已具备该权限（部分类目/新注册账号需要额外申请或达到一定粉丝量）
2. 具备权限后，登录页可增加 `<button open-type="getPhoneNumber">` 一键获取手机号，替代短信验证码输入
